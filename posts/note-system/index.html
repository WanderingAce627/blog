我的笔记系统：三层结构

试过十几个工具之后，我最后留下的结构其实只有三层，而且和软件无关。

#笔记#方法论#效率

我在笔记工具上花的时间，可能比做正经事还多。Notion、Obsidian、Logseq、飞书、各种双链方案……每一次迁移都是一次「重新开始」的幻觉。

真正让它稳定下来的，不是换工具，是换结构。

三层，各管各的

第一层：随手记（当天）

所有突然冒出来的东西都先进这里：一个想法、一段引用、一个报错、一个待查的名词。

关键约束是不分类。分类意味着决策，决策意味着拖延。这一层唯一的要求是：写下它的时间。

我用的就是一个按日期命名的文件，2026-10-20.md，从头往下加。

第二层：主题笔记（长期）

当一个东西在随手记里出现第三次，它才升级到主题笔记。

这是整个系统里最重要的一条规则。重复出现是唯一可靠的信号——它说明这件事真的在我的生活里反复发生，而不是一时的好奇。

主题笔记是「一件事的当前全部认知」。它不是流水账，每写一次就重写一次，把新的理解合并进去：

## 缓存失效的几种策略

- Cache aside：读时回填，写时删缓存。最简单，也最容易出现脏读窗口。
- Write through：写时同步写缓存和库。一致性好，写性能差。
- Write behind：写只写缓存，异步刷库。性能最好，可能丢数据。
  → 2026-09 补充：只在「丢一点数据无所谓」的场景可用，比如浏览量。

注意最后那行带日期的补充。主题笔记要能看出观点的演化，否则它就退化成了资料汇编。

第三层：成品（对外）

文章、方案文档、分享稿。这一层是从第二层里长出来的。

不是每篇主题笔记都值得变成成品，但反过来——没有主题笔记支撑的成品，写出来通常是空的。

为什么不用双链

我用过一整年的双向链接。最后放弃的原因很具体：

双链让「建立关联」的成本降到接近零，于是所有的关联都会被建立。一个记了 500 个节点的库，每个节点连出七八条边，最后那张图没有任何信息量。

我需要的不是「哪些东西相关」，我需要的是「哪些东西重要到值得我专门为它写一页」。前者双链能给，后者只能靠重复出现筛。

工具其实不重要

三层结构用纯文本文件就能实现：

notes/
├── daily/2026-10-20.md
├── topics/缓存策略.md
└── output/静态博客搭建.md

都是 Markdown，都在 Git 里，任何编辑器都能打开。以后换什么工具，cp -r 就搬完了。

真正让我效率变高的不是某个编辑器，是那条「出现三次才升级」的规则。它替我挡掉了 90% 的无效整理。
